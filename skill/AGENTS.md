# Skill 维护规则

> 给所有改这套 skill 的人与 AI。改本目录任何文件前先读这一页。

## 一、正文怎么写

- **只写现行做法**：条件、阈值、步骤、示例。读者只需要知道"现在怎么判"。
- **整句整段重写**：改一条规则就重写那一段，不要在保留的旧句后面追加「（原……）」「（改为……）」「（不再……）」这类补充。
- **禁用表述**：原 skill／原口径／原先／以前／原来是／改为／改成／调整为／替换为／不再／已由……替代／旧版／作废／遗留／v1、v2／本次新增。正文里出现这些词就是写错了。
- **变更过程写仓库 `CHANGELOG.md`**：`SKILL.md`、各模块文档、`README.md`、报告模板一律不写版本沿革。
- **要说明理由就写理由**：写"为什么这么定"（数据、副作用、边界），不写"以前怎么定的"。

## 二、判据口径

- 判据以本目录 `非正常判定标准.md` 全文为准，不是只读判据那三章。`stage1-text/`、`stage2-subject/` 与标准冲突时，**按标准改这两个目录**，不反过来改标准。
- 标准正文两处保存：本目录 `非正常判定标准.md` 与仓库 `非正常判定标准.md`。改一处必须同步另一处，提交前 `diff` 校验一致（仓库那份为匿名版：公开号与企业名替换为"示例：某……"）。
- 顺序：批次（B01、B02）→ 文本（T01–T16）→ 主体（T20–T27）。顺序由实测成本与精确率决定，见 `references/ordering.md`，不按偏好调整。
- 文本步只读 PDF 正文：硬证据（第十二条、第十条）单独成立即非正常；软证据须与第十六条同时成立；只有一项命中记存疑。
- 主体步只审存疑案，且不单独定案：T20–T27 需 ≥2 项成立、或 1 项成立且文本有命中才判非正常；只有 1 项且文本无命中记存疑；数据缺失为待核。批次 B01/B02 仍单独定案。

## 三、阈值与代码

- 阈值只写在 `thresholds.md`；`scripts/text_screen.py` 的常量与之一一对应，改一处必须改另一处。
- 改判据要同步三处：`thresholds.md` 的阈值、`scripts/text_screen.py` 的实现、`非正常判定标准.md` 的条文；改完跑 `scripts/experiment_order.py` 复核精确率。
- 报告格式由 `scripts/build_report.py` 决定，改格式改脚本，不靠手写。

## 四、改完做什么

1. 从 `.dsh/skills/patent-abnormal-screening/` 同步到仓库 `skill/`：

   ```bash
   rsync -a --delete --exclude=cache --exclude=__pycache__ \
     <项目>/非正常/.dsh/skills/patent-abnormal-screening/ <仓库>/skill/
   ```

2. `diff -rq --exclude=cache --exclude=__pycache__` 校验两边一致。
3. 改 `CHANGELOG.md`：中文一句话标题 + 3–6 条要点，只写这次改了什么。
4. 提交并推送 `origin main`，提交人 `arvinooo <2943781161@qq.com>`，不加 AI 署名尾注。

## 五、不要碰

- 不提交客户文本（`测试用例/`）、跑批结果（`results/`）、凭据、`cache/`。
- 不删 `cache/` 下的外部取数结果。
- 不用 `git push --force`。
