# 专利非正常申请筛查（两层）

**第一层只读文本，只判两项：手段、效果。** 依据本目录 `docs/非正常判定标准.md` 全文，判前通读：第一章总则与第三条术语；第二章认定规则（第七条）；第三章手段（第九条~第十五条）；第四章效果（第十六条~第十九条）；第八条类型豁免；第五章批次在第二层用，主体八项按本目录 `rules/` 执行。

第一层三档，两项就地结案：

| 结论 | 条件 | 去向 |
|---|---|---|
| 非正常 | 手段与效果都成立 | 就地出结论，终审 |
| 存疑 | 只成立一项 | 进第二层 |
| 正常 | 两项都不成立 | 就地放行 |

三项之外不加判据。权利要求布局过窄、创造性不足、同类多件拆分、违法公德，不在本流程判定范围。

实用新型不适用效果判据，第一层只判手段：手段成立记存疑，不成立记正常。

**第二层只审存疑案**，判文件之外的事实：

1. **批次**（第二十条、第二十一条）：代理机构月度集中；起草与署名异常。
2. **主体八项**：发明人件数、跨机构、授权发明专利、代理师代理量、①类型、①科技属性、①社保、①主营匹配。
3. 任一项成立 → 非正常；全不成立 → 正常；数据缺失、灰区、查无此人 → 待核。

第二层每一项都是一票否决；数据缺失不默认通过，也不凭空判不过。


## 二、铁律

0. **先查缓存再取数**：`./cache/`（company / inventor / agent_month）、`results/` 同批结果、skill 包内 `cache/`。命中条件为口径一致且在有效期内；不满足按未命中处理，取完写回。报告标注「缓存值（原始取数日）」。
1. **第一层不取外部数据**：文本层只用文件本身。
2. **认定规则**：第一层两项都成立即非正常；只成立一项为存疑，进第二层；两项都不成立为正常。第二层任一项成立即非正常；全不成立为正常；数据缺失为待核。单项判据不得单独认定。
3. **数据拿不到 → 待核**：不默认通过，也不凭空判不过，写清缺什么。
4. **每案挂证据**：条款编号 + 原文位置（权项号、段落号）。证据写进 `cases/*.json`，报告只写人话原因。
5. **判据以原文为准**：看技术方案本身，名称与著录项只作补充。用户给的申请人与著录项不一致时标注。
6. **复核提示不当结论**：脚本 `hints`（结构案、仅缺验证数据）是提示。结构案须看完附图与装配关系再定。

## 三、三档与状态

| 档 | 含义 | 出现在 |
|---|---|---|
| 非正常 | 第一层两项成立；或第二层任一项成立 | 第一层、第二层 |
| 正常 | 第一层零项；或第二层全不成立 | 第一层、第二层 |
| 待核 | 第二层数据缺失、灰区、查无此人 | 第二层 |

对外表述：正常即正常；存疑且二层全过 → 正常；数据缺失 → 待核。

第二层判定表：

| 项 | 成立条件 | 细则文件 |
|---|---|---|
| 批次·机构集中 | 第二十条：同月 ≥10 件且 ≥6 家，引用 <20%、背景达 400 字 <50%；或 12 个月 ≥30 件且 ≥15 家 | `rules/30-batch.md` |
| 批次·署名异常 | 第二十一条四项任一 | 同上 |
| 发明人件数 | 剔重名后 ≥5 件 | `rules/40-inventor.md` |
| 跨机构 | 聚组后 ≥3 组 | `rules/50-cross-org.md` |
| 授权发明专利 | 0 件且申请人为企业；院校院所医院自然人不适用 | `rules/60-subject.md` §1e |
| 代理师代理量 | ≥300 件；查无此人记待核 | `rules/65-agency.md` |
| ①类型 | 自然人/个体户；或文化/传媒/茶业类且主营无交集 | §1a |
| ①科技属性 | 主业文化/传媒/茶业/贸易/餐饮/咨询/投资/房地产/物流且无研发范围 | §1b |
| ①社保 | 参保 <3 | §1c |
| ①主营匹配 | 与技术对象无关，且非院校非医院 | §1d |

院校、医院不因身份命中：已确认正常样本的申请人中占 55%，非正常样本中占 2%。

## 四、报告格式

**只用表格，不写叙述、不写说明段。** 报告给委托方与律师看，只写三件事：哪件不正常、哪件正常、不正常的理由。

由 `scripts/build_report.py` 生成：

```bash
python3 scripts/build_report.py 结果.json -o 报告.md --title 批次名
```

报告固定结构：

```text
# 批次名

**本报告仅供参考，不作为非正常判断的唯一依据。**

合计 34 件：非正常 6 件，正常 28 件，待核 0 件。

## 一、非正常（6 件）

| # | 名称 | 申请人 | 原因 |
|---|---|---|---|
| 1 | 一种智能家居光电设备控制方法及系统 | 某电力科技有限公司 | 权利要求通篇是功能模块，没有结构、没有流程 |

## 二、正常（28 件）

| # | 名称 | 申请人 |
|---|---|---|
| 1 | 一种不锈钢钢板的焊接缺陷识别方法及系统 | 某机械科技有限公司 |

## 三、待核（0 件）

无。
```

写法要求：

- 开头固定免责声明。
- 三档：非正常、正常、待核。第二层全过写正常；只有数据缺失写待核。
- 非正常表写原因：一句话，写文档里看到的事实，不写条款号、不写维度代号。
- 正常表只写名称与申请人，逐件列全。
- 待核表只写"差什么"：批次、主体数据还是灰区。
- 不写术语：不出现「权1／独权／从权／上位」。
- 不写批次口径、送审文件数、取数日、成本；留在 `cases/*.json`。
