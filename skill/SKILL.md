# 专利非正常申请筛查

## 一、分两层

| 层 | 输入 | 成本 | 出什么 |
|---|---|---|---|
| 第一层 文本 | PDF 正文；同批 ≥2 件时加跨案核对 | 0 查询 | 非正常（结案）/ 存疑（进第二层）/ 正常（结案） |
| 第二层 主体 | 只跑第一层存疑案 | 每主体 1 次 | 非正常 / 正常 / 待核 |

一句话：**这件专利是为了保护技术，还是为了凑数。** 第一层看正文写没写出"怎么做、凭什么有效"、同批是不是把一件产品拆成多件；第二层看申请人、发明人像不像真在做这件事。

## 二、第一层：PDF 正文 + 跨案

### 判什么

| 组 | 编号 | 看什么 |
|---|---|---|
| 手段 | T01–T08、T15 | 权 1 是通用动作、功能性模块、部件罗列，还是结构堆砌 |
| 效果 | T11、T16 | 有没有引用在先文献、性能测试表、测试结果数值 |
| 救援 | T09 | 有公式、变量定义的，手段判据不成立 |
| 跨案 | T13、T14 | 同批同申请人的多件是不是拆分型、复制型 |

### 判决

| 条件 | 结论 | 下一步 |
|---|---|---|
| T08 结构堆砌 或 T04 功能性模块 成立 | 非正常 | 结束 |
| T13 拆分型 或 T14 复制型 成立（同批 ≥2 件） | 非正常 | 结束，报告写组内件数与产品线 |
| 其余手段条款成立，且 T11 同时成立 | 非正常 | 结束 |
| 只有单一手段条款、只有 T11、或仅引用在先文献 | 存疑 | 进第二层 |
| 无任何命中 | 正常 | 结束，不核主体 |

硬证据只有 T04、T08 两条。跨案两条是一票否决：按同申请人成组的事实定案，不与 T11 搭配。实用新型不适用 T11，只按手段判：硬证据记非正常，软证据记存疑进第二层。

### 拆分型与复制型

- 拆分型：同申请人 ≥2 件、申请日跨度 ≤12 个月、组内发明名称全围同一产品/设备的 → 非正常，组内各件都算。
- 复制型：两件正文 20 字片段重合 ≥50%，技术问题与原理一致、差异仅在参数的 → 非正常，两件都算。
- 单件送审记"未核（单件）"，不算命中。
- 成组口径、判例、重合率算法见 `stage1-text/cross-case.md`。

## 三、第二层：主体事实

只跑第一层的存疑案，顺序固定：

```text
0 前置：查专精特新（qcc operation get_honor_info）
   国家级专精特新"小巨人"、省级专精特新中小企业 → T23–T27 全部跳过：不取数、不否决
   其余（含创新型中小企业、科技型中小企业、高新技术企业） → 照常跑
1 人：T20 发明人件数、T21 跨机构、T22 代理师代理量
2 企业：T23 授权发明专利、T24 类型、T25 科技属性、T26 社保、T27 主营匹配
   专精特新命中时，这一行全部跳过
```

判决：**八项一票否决，任一项成立 → 非正常**；全不成立 → 正常；数据取不到 → 待核，不猜，也不默认放过。

进入第二层的案子在第一层已有文本命中，一项主体事实就够定案。豁免只限 T23–T27，T20/T21/T22 照常否决——专精特新证明公司有研发实力，证明不了这篇没抄、这个人没爆量。豁免口径见 `stage2-subject/S7-exemptions.md`。

## 四、一件案子走一遍

`CN120777670A 地源热泵系统的安全监测方法及装置`，申请人北京华清洁能。

| 数什么 | 值 | 说明 |
|---|---|---|
| 权 1 的附图标记 | 0 个 | 没有任何结构描述 |
| 权 1 由"获取/判断/输出"起头的分句 | 100% | 全是通用动作 |
| "单元/模块，用于" | 4 处 | 功能性模块 |
| 编号实施例 | 0 个 | 没给可实现的方案 |
| 性能测试表 / 测试数值 | 0 / 0 | 没给验证数据 |
| 背景技术引用在先文献 | 0 处 | 没做检索比对 |

第二层不用跑：T04（功能性模块 ≥3 处且无模型、无实施例）单独成立 → 非正常。

对照：`CN118852128A 含2-吲哚酮的喹唑啉衍生物`，9 个实施例、2 张性能测试表、66 处带单位参数 → T11 放行，文本无命中 → 正常，不查主体。

## 五、数据从哪来、花多少

| 查什么 | 平台 | 成本 |
|---|---|---|
| 授权发明专利件数 | incoPat | 每申请人 1 次，约 75 秒 |
| 社保、经营范围、行业 | 企查查 `qcc company get_company_registration_info` | 每申请人 1 次，约 1 秒 |
| 专精特新荣誉 | 企查查 `qcc operation get_honor_info` | 每申请人 1 次，约 1 秒 |
| 代理师 12 个月代理量 | 香橼树代理师月度统计 | 每人 1 次 |
| 发明人名下件数 | incoPat | 每人 1 次，约 75 秒 |

去重很关键：446 件案子只对应 203 个申请人、295 个发明人。按件查会白花 4–15 倍时间。

## 六、怎么跑

```bash
# 第一层：一条命令出三档，逐案一行 JSON（默认 8 进程；PDF 文本落 cache/pdftext，重跑不再抽）
python3 scripts/text_screen.py <某批 PDF 目录> --json 结果.json [--workers 8]

# 第一层跨案：按申请人成组，人读标题判拆分型，重合率按 cross-case.md 的算法算
# 第二层：只对 verdict=存疑 的案子跑 S1–S7
python3 scripts/company_lookup.py --apps-file 申请人.json      # T23–T27 与专精特新：去重、跳过院校/自然人、缓存优先、积分耗尽即停
python3 scripts/inco_granted.py --json 申请人基准日.json       # T23 批量查（10 家一条检索式）
python3 scripts/xys_agent.py <代理师> --anchor <申请日> --agency "<代理机构>"   # 跨所直接记 na，不开浏览器

# 出报告
python3 scripts/build_report.py 结果.json -o 报告.md --title 批次名

# 复核阈值是否还站得住（会重算全部数字）
python3 scripts/experiment_order.py --pos <非正常样本目录> --neg <正常样本目录>
```

主体要调平台，命令见 `references/data-sources.md`；缓存 90 天，查过的别重查。

## 七、什么时候不适用

- **创造性不足**：技术简单不算非正常，按审查意见处理。
- **权利要求写窄了**、**违法公德**：不在本流程范围。
- **院校、医院、研究所**：不因身份命中，技术方向超出经营范围是常态。
- **实用新型**：不适用 T11；没有手段命中的列存疑，不放正常。

## 九、边界

- 只判上面列出的判据，不自创指纹、模板套话、相似度打分。
- 数据拿不到记待核，不默认通过，也不凭空判不过。
- 结构案（T08、T05）出结论时附"核对附图"，图文排版会让附图标记数差 2–26 个。
- 拆分型按标题成组判，产品线边界靠人读标题；判错的后果是整组判非正常，判例见 `cross-case.md`。
- 文本无命中直接按正常提交，不核主体：主体是空的案子本流程识别不了。
