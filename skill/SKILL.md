# 专利非正常申请筛查（两层流程）

**第一层只读文件**：手段、效果、批次三项判据。不取外部数据，出"非正常 / 存疑 / 可提交"三档。
**第二层只处理存疑案**：九项主体面板全跑——发明人件数、跨机构、授权发明专利、代理师代理量、分类号集中、主体类型、科技属性、社保人数、主营匹配。任一项成立即非正常，全不成立即可提交。

这样排的依据：文本层在 516 件已确认样本上处理掉 77% 的案子，只有约四分之一需要取数。各判据的实测数据见 `cases.md`。

---

## 一、流程

```text
第 -1 步 查缓存（PATENT_CACHE_DIR，默认 ./cache）+ results/ 同批结果，命中直接用
第 0 步  读案：从首页取申请人、发明人、代理机构、申请日、类型；无申请日则用查询日做窗口锚点
第 1 步  文本层（本地，不取数）：python3 scripts/text_screen.py <本批目录>
         1a 手段判据（第八条~第十三条）
         1b 效果判据（第十四条~第十七条）
         1c 批次判据（第十八条~第二十条）——件数与申请人数按代理机构代码查该月全部申请，见 rules/30-batch.md
         输出三档
第 2 步  主体层（只对"存疑"案，九项全跑，任一成立即非正常）
         2a 第一发明人 12 个月内有效件数（剔重名）≥5
         2b 第一发明人跨机构组数 ≥3
         2c 授权发明专利 = 0 且申请人为企业
         2d 代理师代理量 ≥300（本所口径）
         2e 分类号 G06/H04 且主体无科技属性
         2f ①类型：自然人，或文化/传媒/茶业/贸易类且主营无交集
         2g ①科技属性：无研发类经营范围且技术对象属信息类
         2h ①社保：参保 <3 且无授权发明且无研发范围
         2i ①主营匹配：与技术对象无交集且非院校非医院
         九项任一成立 → 非正常；全不成立 → 可提交；数据缺失 → 存疑
第 3 步  出报告
```

**成本**：第 1 步本地解析，一批 80 件约 15 秒。第 2 步按人级、机构级去重后复用缓存，实际取数次数取决于存疑案涉及的发明人数。

## 二、铁律

0. **先查缓存再取数**：`./cache/`（company / inventor / agent_month）、`results/` 同批结果、skill 包内 `cache/`。命中条件为口径一致且在有效期内；不满足按未命中处理，取完写回。报告标注「缓存值（原始取数日）」。
1. **第一层不取数**：文本层只用文件本身。批次判据需要的件数与申请人数，按代理机构代码一次性查该月全部申请，不逐个申请人查。
2. **三项判据中满足两项认定非正常，满足一项为存疑，零项为可提交**（第六条）。单项不得认定。
3. **数据拿不到 → 保持存疑**：不默认通过，也不凭空判不过。写清缺什么数据。
4. **每案挂证据**：条款编号 + 原文位置（权项号、段落号）。证据写进 `cases/*.json`，报告只写人话原因。
5. **判据以原文为准**：看技术方案本身，名称与著录项只作补充。用户给的申请人与著录项不一致时标注。
6. **复核提示不当结论**：脚本给出的 `hints`（结构案、仅缺数据）是提示。结构案须看完附图与装配关系再定，不得直接出非正常。

## 三、三档与状态

| 档 | 含义 | 下一步 |
|---|---|---|
| 非正常 | 三项判据命中两项以上 | 出结论，附条款；结构类与仅缺数据类加复核提示 |
| 存疑 | 命中一项 | 进第二层取数 |
| 可提交 | 零项 | 放行，报告写「文本层未见异常特征」 |

第二层判定：

| 项 | 成立条件 |
|---|---|
| 发明人件数 | 剔重名后 ≥5 件 |
| 跨机构 | 聚组后 ≥3 组 |
| 授权发明专利 | 0 件且申请人为企业 |
| 代理师代理量 | ≥300 件 |
| 分类号集中 | 主分类 G06/H04 且主体无科技属性 |
| ①类型 | 自然人，或文化/传媒/茶业/贸易类且主营无交集 |
| ①科技属性 | 无研发类经营范围且技术对象属信息类 |
| ①社保 | 参保 <3 且无授权发明且无研发范围 |
| ①主营匹配 | 与技术对象无交集且非院校非医院 |

九项任一成立即非正常；全不成立可提交；数据缺失存疑。

四项画像为什么都带条件：主体身份本身在正常案里同样常见（已确认正常样本中院校占 76%、参保 <3 占 33%），单凭身份定案会整批误判。所以每项都写成"身份 + 事实"的组合，身份只作入口，事实才定案。

> 「可提交」是筛查结论，不等于确认正常：文本层在已确认非正常样本上约 3% 落在这一档。

## 四、报告格式

**只用表格，不写叙述。** 由 `scripts/build_report.py` 从 `text_screen.py` 的结果直接生成：

```bash
python3 scripts/text_screen.py <本批目录> --json 结果.json
python3 scripts/build_report.py 结果.json -o 报告.md --title 批次名
```

报告固定三块：

```text
# 批次名

合计 81 件：非正常 72 件，存疑 8 件，可提交 1 件。

## 一、非正常

| # | 名称 | 申请人 | 原因 |
|---|---|---|---|
| 1 | 一种智能家居光电设备控制方法及系统 | 某电力科技有限公司 | 权利要求通篇是功能模块，没有结构、没有流程 |

批次：12 个月 39 件、34 家申请人，引用 3%、长背景 31%。

## 二、存疑

| # | 名称 | 申请人 | 差什么 |
|---|---|---|---|
| 1 | 一种不锈钢钢板的焊接缺陷识别方法及系统 | 某机械科技有限公司 | 仅批次一项成立，文本层面未见其他异常 |
```

写法要求：

- 每案一行，原因一句话，写"文档里看到的事实"，不写条款号、不写维度代号。
- 批次事实只写一次，放表下一行，不进每行。
- 存疑表只写"差什么"，写清缺的是手段、效果还是批次。
- 可提交的案子不列表。
- 不写术语：不出现「权1／独权／从权／上位」。
- 报告不带证据原文、取数日、成本；这些留在 `cases/*.json`。
