# 专利非正常申请筛查（两层流程）

**第一层只读文件**：手段、效果、批次三项判据，判的是 PDF 主体写得怎么样。判定依据是本目录 `docs/非正常判定标准.md` 全文，判前通读：第三章手段、第四章效果、第五章批次是三项判据的条文；第二章认定规则与技术类型分别适用（第七条豁免）；第六章主体核查对应第二层；第七章核查流程；第八章使用限制（结构案须复核、可提交不等于确认正常）。三项之外不加判据；文件本身的其他问题——权利要求布局过窄、创造性不足、违法公德、同类多件拆分——不在本流程的判定范围，不据此出结论。
**第二层只处理存疑案**：判**文件之外**的主体事实——发明人件数、跨机构、授权发明专利、代理师代理量、①类型、①科技属性、①社保、①主营匹配。任一项成立即非正常，全不成立即可提交。

这样排的依据：文本层在 516 件已确认样本上处理掉 77% 的案子，只有约四分之一需要取数。各判据的实测数据见 `cases.md`。

## 一、流程

```text
第 -1 步 查缓存（PATENT_CACHE_DIR，默认 ./cache）+ results/ 同批结果，命中直接用
第 0 步  读案：从首页取申请人、发明人、代理机构、申请日、类型；无申请日则用查询日做窗口锚点
第 1 步  文本层（本地，不取数）：python3 scripts/text_screen.py <本批目录>
         判定依据：docs/非正常判定标准.md 全文 ＋ rules/（执行细则与阈值）；两者冲突以标准为准
         1a 手段判据（第八条~第十三条）           rules/10-means.md
         1b 效果判据（第十四条~第十七条）         rules/20-effect.md
         1c 批次判据（第十八条~第二十条）——件数与申请人数按代理机构代码查该月全部申请，rules/30-batch.md
         输出三档
第 2 步  第二层（只对"存疑"案，八项全跑，任一成立即非正常）
         1  前置资质：查专精特新（rules/90-exemptions.md），命中则企业类五项标豁免
         2a 第一发明人 12 个月内有效件数（剔重名）≥5          rules/40-inventor.md
         2b 第一发明人跨机构组数 ≥3                          rules/50-cross-org.md
         2c 授权发明专利 = 0 且申请人为企业                    rules/60-subject.md §1e
         2d 代理师代理量 ≥300（本所口径；查无此人记 na）        rules/65-agency.md
         2e ①类型：自然人/个体户；或文化/传媒/茶业类且主营无交集                §1a
         2f ①科技属性：主业文化/传媒/贸易/餐饮/咨询/投资/房地产/物流且无研发范围       §1b
         2g ①社保：参保 <3                                    §1c
         2h ①主营匹配：与技术对象无关且非院校非医院            §1d
         八项任一成立 → 非正常；全不成立 → 可提交；数据缺失 → 存疑
第 3 步  出报告
```

**成本**：第 1 步本地解析，一批 80 件约 15 秒。第 2 步按人级、机构级去重后复用缓存，实际取数次数取决于存疑案涉及的发明人数。

## 二、铁律

0. **先查缓存再取数**：`./cache/`（company / inventor / agent_month）、`results/` 同批结果、skill 包内 `cache/`。命中条件为口径一致且在有效期内；不满足按未命中处理，取完写回。报告标注「缓存值（原始取数日）」。
1. **第一层不取数**：文本层只用文件本身。批次判据需要的件数与申请人数，按代理机构代码一次性查该月全部申请，不逐个申请人查。
2. **三项判据中满足两项认定非正常，满足一项为存疑，零项为可提交**（第六条）。单项不得认定。
3. **数据拿不到 → 保持存疑**：不默认通过，也不凭空判不过。写清缺什么数据。
4. **每案挂证据**：条款编号 + 原文位置（权项号、段落号）。证据写进 `cases/*.json`，报告只写人话原因。
5. **判据以原文为准**：看技术方案本身，名称与著录项只作补充。用户给的申请人与著录项不一致时标注。
6. **复核提示不当结论**：脚本给出的 `hints`（结构案、仅缺数据）是提示。结构案须看完附图与装配关系再定，不得直接出非正常。

## 三、三档与状态

| 档 | 含义 | 下一步 |
|---|---|---|
| 非正常 | 三项判据命中两项以上 | 出结论，附条款；结构类与仅缺数据类加复核提示 |
| 存疑 | 命中一项 | 进第二层取数 |
| 可提交 | 零项 | 放行，报告写「文本层未见异常特征」 |

第二层判定：

| 项 | 成立条件 | 细则文件 |
|---|---|---|
| 发明人件数 | 剔重名后 ≥5 件 | `rules/40-inventor.md` |
| 跨机构 | 聚组后 ≥3 组 | `rules/50-cross-org.md` |
| 授权发明专利 | 0 件且申请人为企业；院校院所医院自然人不适用 | `rules/60-subject.md` §1e |
| 代理师代理量 | ≥300 件；查无此人记 na，不参与否决 | `rules/65-agency.md` |
| ①类型 | 自然人/个体户；或文化/传媒/茶业类且主营无交集 | §1a |
| ①科技属性 | 主业文化/传媒/贸易/餐饮/咨询/投资/房地产/物流且无研发类经营范围 | §1b |
| ①社保 | 参保 <3 | §1c |
| ①主营匹配 | 与技术对象无关，且非院校非医院 | §1d |

八项任一成立即非正常；全不成立可提交；数据缺失存疑。八项之外不加项、不改条件。

四项主体项一律一票否决。仍保留条件的只有两处：文化/传媒/茶业类须主营与技术主题无交集，①主营匹配须排除院校与医院——这两处的身份或范围本身不足以定案，须落到具体事实。院校、医院不因身份命中：已确认正常样本中占 76%，非正常样本中占 2%。

> 「可提交」是筛查结论，不等于确认正常：文本层在已确认非正常样本上约 3% 落在这一档。

## 四、报告格式

**只用表格，不写叙述、不写说明段。** 报告给委托方与律师看，只写他们要看的三件事：哪件不正常、哪件正常、不正常的理由。批次口径、送审文件数、去重过程、取数日期、证据原文，一律不上报告。

由 `scripts/build_report.py` 生成：

```bash
python3 scripts/build_report.py 结果.json -o 报告.md --title 批次名
```

报告固定结构：

```text
# 批次名

**本报告仅供参考，不作为非正常判断的唯一依据。**

合计 34 件：非正常 6 件，正常 28 件，待核 0 件。

## 一、非正常（6 件）

| # | 名称 | 申请人 | 原因 |
|---|---|---|---|
| 1 | 一种智能家居光电设备控制方法及系统 | 某电力科技有限公司 | 权利要求通篇是功能模块，没有结构、没有流程 |

## 二、正常（28 件）

| # | 名称 | 申请人 |
|---|---|---|
| 1 | 一种不锈钢钢板的焊接缺陷识别方法及系统 | 某机械科技有限公司 |

## 三、待核（0 件）

无。
```

写法要求：

- 开头固定一句免责声明：「本报告仅供参考，不作为非正常判断的唯一依据。」
- 三档对外表述：可提交 → 正常；存疑 → 待核。合计件数与各表件数一致。
- 非正常表写原因：一句话，写文档里或名下看到的事实，不写条款号、不写维度代号。
- 正常表只写名称与申请人，逐件列全，便于逐件核对。
- 待核表只写"差什么"，写清缺的是件数、工商数据还是代理量；没有待核案写"无"。
- 不写术语：不出现「权1／独权／从权／上位」。
- 不写批次口径、送审文件数、去重说明、取数日、成本；这些留在 `cases/*.json`。

## 五、配套文件

- `rules/00-thresholds.md` — 阈值唯一出口（第一层文本判据 + 第二层主体面板）
- `rules/10-means.md` — 手段判据细则（第八条~第十三条）
- `rules/20-effect.md` — 效果判据细则（第十四条~第十七条）
- `rules/30-batch.md` — 批次判据与取数方法（第十八条~第二十条）
- `rules/40-inventor.md` — 第二层：发明人件数（含剔重名：交集式）
- `rules/50-cross-org.md` — 第二层：跨机构
- `rules/60-subject.md` — 第二层：①类型 / ①科技属性 / ①社保 / ①主营匹配 / 授权发明专利
- `rules/65-agency.md` — 第二层：代理师代理量
- `rules/90-exemptions.md` — 专精特新豁免（企业类五项 + 授权发明专利）
- `docs/非正常判定标准.md` — 判定标准全文（八章三十条），报告可给委托方
- `data-sources.md` — 取数字段码、检索式、缓存
- `cases.md` — 标定数据与判例
- `scripts/text_screen.py` — 第一层打分
- `scripts/build_report.py` — 结果 JSON 转简洁报告
- `scripts/extract_pdf.py` — 解析；`scripts/cache.py`、`inco_*.py`、`xys_agent.py` — 第二层取数
