# 专利非正常申请筛查（两层流程）

**第一层只读文本，判两项：手段、效果。** 判定依据是本目录 `docs/非正常判定标准.md` 全文，判前通读：第一章总则与第二章的术语（第三条）、认定规则（第六条）；第三章手段（第八条~第十三条）；第四章效果（第十四条~第十七条）；第七条的类型豁免；第七章核查流程；第八章使用限制。第五章批次与第六章主体在第二层用。三项之外不加判据；文件本身的其他问题——权利要求布局过窄、创造性不足、违法公德、同类多件拆分——不在本流程的判定范围，不据此出结论。

第一层只有两种结论：

- **非正常**：手段与效果都成立。三项判据已占两项，批次与主体都改不了这个结论。
- **待核**：其余全部。文本两项没全中，不代表案子没问题——批次与主体还没查。

**第二层处理第一层没定案的案子**，按顺序走：

1. **批次**（第十八条~第二十条）：按代理机构代码查该月全部申请，成立即得一项。
2. 手段、效果、批次合计两项以上 → 非正常，不必往下查。
3. **主体八项**：发明人件数、跨机构、授权发明专利、代理师代理量、①类型、①科技属性、①社保、①主营匹配。
4. 主体任一成立 → 非正常；全不成立 → 三项合计一项为存疑、零项为可提交。

主体八项一票否决：任一项成立即非正常，不看三项合计几项。

这样排的依据：516 件已确认样本上，第一层直接定案 237 件（46%），其余 279 件进第二层。第二层先查批次，批次与已得判据合计两项的案子不必再核主体。各判据实测数据见 `cases.md`。

## 一、流程

```text
第 -1 步 查缓存（PATENT_CACHE_DIR，默认 ./cache）+ results/ 同批结果，命中直接用
第 0 步  读案：从首页取申请人、发明人、代理机构、申请日、类型；无申请日则用查询日做窗口锚点
第 1 步  第一层：只读文本，判手段与效果（不取外部数据）
         1.0 通读 docs/非正常判定标准.md 全文（八章三十条），不通读不下结论
         1.1 逐件审：手段（第八条~第十三条）→ 效果（第十四条~第十七条）
             每条按第三条术语取值、按第七条判类型是否豁免
         1.2 细则与阈值查 rules/（怎么算、用什么口径）；与标准冲突以标准为准
         1.3 scripts/text_screen.py 可先跑一遍做初筛，输出只作对照
         两项都成立 → 非正常；其余 → 待核，进第 2 步
第 2 步  第二层（只对"待核"案）
         2a 批次：按代理机构代码查该月全部申请，判第十八条~第二十条      rules/30-batch.md
         2b 手段+效果+批次合计 ≥2 项 → 非正常，出结论，不查主体
         2c 前置资质：查专精特新（rules/90-exemptions.md），命中则企业类五项标豁免
         2d 第一发明人 12 个月内有效件数（剔重名）≥5                     rules/40-inventor.md
         2e 第一发明人跨机构组数 ≥3                                     rules/50-cross-org.md
         2f 授权发明专利 = 0 且申请人为企业                               rules/60-subject.md §1e
         2g 代理师代理量 ≥300（本所口径；查无此人记 na）                   rules/65-agency.md
         2h ①类型：自然人/个体户；或文化/传媒/茶业类且主营无交集                     §1a
         2i ①科技属性：主业文化/传媒/茶业/贸易/餐饮/咨询/投资/房地产/物流且无研发范围     §1b
         2j ①社保：参保 <3                                             §1c
         2k ①主营匹配：与技术对象无关且非院校非医院                       §1d
         主体任一成立 → 非正常；全不成立 → 三项合计一项存疑、零项可提交
第 3 步  出报告
```

**成本**：第 1 步本地解析，一批 80 件约 15 秒。第 2 步批次按机构去重，一条查询覆盖该机构整月；主体八项按人级、机构级去重复用缓存。

## 二、铁律

0. **先查缓存再取数**：`./cache/`（company / inventor / agent_month）、`results/` 同批结果、skill 包内 `cache/`。命中条件为口径一致且在有效期内；不满足按未命中处理，取完写回。报告标注「缓存值（原始取数日）」。
1. **第一层不取外部数据**：文本层只用文件本身。批次属第二层，按代理机构代码一次覆盖整月，不逐案查。
2. **认定规则**：三项判据中命中两项认定非正常，命中一项为存疑，零项为可提交（第六条）；主体八项任一成立即非正常，不看三项合计（第二十一条）。单项判据不得单独认定。
3. **数据拿不到 → 保持存疑**：不默认通过，也不凭空判不过。写清缺什么数据。
4. **每案挂证据**：条款编号 + 原文位置（权项号、段落号）。证据写进 `cases/*.json`，报告只写人话原因。
5. **判据以原文为准**：看技术方案本身，名称与著录项只作补充。用户给的申请人与著录项不一致时标注。
6. **复核提示不当结论**：脚本给出的 `hints`（结构案、仅缺数据）是提示。结构案须看完附图与装配关系再定，不得直接出非正常。

## 三、三档与状态

| 档 | 含义 | 出现在 |
|---|---|---|
| 非正常 | 手段与效果两项成立；或第二层三项合计 ≥2；或主体任一项成立 | 第一层、第二层 |
| 存疑 | 三项合计一项，且主体全不成立 | 第二层 |
| 可提交 | 三项合计零项，且主体全不成立 | 第二层 |
| 待核 | 第一层两项未全成立，第二层未做或数据缺失 | 第一层、第二层中断 |

对外表述：非正常 → 非正常；存疑与待核 → 待核；可提交 → 正常。存疑即标准第六条所称"可疑"。

第二层判定：

| 项 | 成立条件 | 细则文件 |
|---|---|---|
| 批次 | 第十八条~第二十条任一款成立 | `rules/30-batch.md` |
| 发明人件数 | 剔重名后 ≥5 件 | `rules/40-inventor.md` |
| 跨机构 | 聚组后 ≥3 组 | `rules/50-cross-org.md` |
| 授权发明专利 | 0 件且申请人为企业；院校院所医院自然人不适用 | `rules/60-subject.md` §1e |
| 代理师代理量 | ≥300 件；查无此人记 na，不参与否决 | `rules/65-agency.md` |
| ①类型 | 自然人/个体户；或文化/传媒/茶业类且主营无交集 | §1a |
| ①科技属性 | 主业文化/传媒/茶业/贸易/餐饮/咨询/投资/房地产/物流且无研发类经营范围 | §1b |
| ①社保 | 参保 <3 | §1c |
| ①主营匹配 | 与技术对象无关，且非院校非医院 | §1d |

主体八项任一成立即非正常；全不成立可提交。八项之外不加项、不改条件。

主体项一律一票否决，两处保留条件：文化/传媒/茶业类须主营与技术主题无交集，①主营匹配须排除院校与医院——这两处的身份或范围本身不足以定案，须落到具体事实。院校、医院不因身份命中：已确认正常样本的申请人中占 76%，非正常样本中占 2%。

> 「可提交」是筛查结论，不等于确认正常：文本层在已确认非正常样本上约 1.5% 两项全不成立，最终由第二层的批次与主体决定是否放行。

## 四、报告格式

**只用表格，不写叙述、不写说明段。** 报告给委托方与律师看，只写他们要看的三件事：哪件不正常、哪件正常、不正常的理由。批次口径、送审文件数、去重过程、取数日期、证据原文，一律不上报告。

由 `scripts/build_report.py` 生成：

```bash
python3 scripts/build_report.py 结果.json -o 报告.md --title 批次名
```

报告固定结构：

```text
# 批次名

**本报告仅供参考，不作为非正常判断的唯一依据。**

合计 34 件：非正常 6 件，正常 28 件，待核 0 件。

## 一、非正常（6 件）

| # | 名称 | 申请人 | 原因 |
|---|---|---|---|
| 1 | 一种智能家居光电设备控制方法及系统 | 某电力科技有限公司 | 权利要求通篇是功能模块，没有结构、没有流程 |

## 二、正常（28 件）

| # | 名称 | 申请人 |
|---|---|---|
| 1 | 一种不锈钢钢板的焊接缺陷识别方法及系统 | 某机械科技有限公司 |

## 三、待核（0 件）

无。
```

写法要求：

- 开头固定一句免责声明：「本报告仅供参考，不作为非正常判断的唯一依据。」
- 三档对外表述：可提交 → 正常；存疑、待核 → 待核。合计件数与各表件数一致。
- 非正常表写原因：一句话，写文档里或名下看到的事实，不写条款号、不写维度代号。
- 正常表只写名称与申请人，逐件列全，便于逐件核对。
- 待核表只写"差什么"：差批次、差主体数据还是只够一项判据，写清楚；没有待核案写"无"。
- 不写术语：不出现「权1／独权／从权／上位」。
- 不写批次口径、送审文件数、去重说明、取数日、成本；这些留在 `cases/*.json`。

## 五、配套文件

- `rules/20-effect.md` — 效果判据细则（第十四条~第十七条）

- `rules/40-inventor.md` — 第二层：发明人件数（含剔重名：交集式）
- `rules/50-cross-org.md` — 第二层：跨机构
- `rules/60-subject.md` — 第二层：①类型 / ①科技属性 / ①社保 / ①主营匹配 / 授权发明专利
- `rules/65-agency.md` — 第二层：代理师代理量
- `rules/90-exemptions.md` — 专精特新豁免（企业类五项 + 授权发明专利）
