# 专利非正常申请筛查

## 一、两阶段

```text
第一阶段  只读 PDF 正文，不取外部数据
          任一手段判据成立，或第十六条有益效果段复述成立  → 非正常（终审，不再核主体）
          无手段判据，且满足放行条件                        → 正常（放行）
          其余                                              → 存疑

第二阶段  只对存疑案，先批次后主体
          先跑批次（一条机构查询覆盖整批）：B01、B02
          再跑主体八项：T20–T27（人级、企业级各一次，缓存复用）
          任一项成立 → 非正常；全不成立 → 正常；数据缺失/灰区/查无此人 → 待核
```

放行条件：说明书编号实施例 ≥2 且（有性能测试表 或 带单位参数 ≥25 处）。
**实用新型不适用放行条件**，第一阶段只判手段：命中记非正常，未命中记存疑。

## 三、执行顺序

| 步 | 做什么 | 成本 |
|---|---|---|
| -1 | 查缓存：`./cache/`、`results/` 同批结果、skill 包内 cache；命中直接用，标注原始取数日 | 0 |
| 0 | 读案：首页著录项（申请人、发明人、代理机构、申请日、类型） | 0 |
| 1 | 第一阶段：`procedure.md` 的抽取与计数 → 按标准逐条核 → 出三档 | 本地 |
| 1.5 | 可选：`scripts/text_screen.py` 先跑一遍做对照，结果不作结论 | 本地 |
| 2a | 第二阶段批次：B01、B02（一条机构查询覆盖整批） | 每次机构 1 查询 |
| 2b | 第二阶段主体：T20–T27，按人、按企业去重取数 | 每人/每家各 1 次 |
| 2c | 兜底：S6 研发过程记录（前八项取不到或事实与文本不符时） | 人工 |
| 3 | 出报告：三档结论 + 触发项 + 证据 + 未核项 | — |

批次先于主体：批次一条查询覆盖整批，主体逐案逐人。先跑批次能整批定案，省掉后续取数。

## 四、边界

- 只判本目录列出的判据，不自创指纹、模板套话、相似度打分。
- **不在本流程范围**：创造性不足、权利要求布局过窄、同类多件拆分、违法公德。这些按审查意见或另设流程处理。
- 院校、医院不因身份命中；企业阈值不得直接套用到院校院所。
- 结构案触发 T08 时，附"核对附图"提示，须复核后再定。
- 数据拿不到记待核，不默认通过，也不凭空判不过。

## 五、报告

每件出一张判定单（字段见 `stage1-text/procedure.md` 第四节）。第二阶段只在判定单上追加：B01/B02 与 T20–T27 的逐项结论、数据来源与取数日、豁免标记。
