# 专利非正常申请筛查

**输入**：专利公开文本（PDF 或 Word，一份或多份同批）+ 案件明细（申请人 / 第一发明人 / 其余发明人 / 代理机构 / 代理人）
**输出**：正常 / 非正常 / 待核查，附逐维结论与证据（段落号、权项号、数据来源 + 取数日）

全维口径：发明人计数先剔重名；跨机构按关联聚组判；企业类资质可按专精特新豁免；代理师阈值 300 件/12 个月。
③ 按「先归四类再分流」判：不属于四类直接过、不看创新度；生活类/计算机算法一票不过；只有机械装置、方法步骤图的系统才检索对比文件、算特征覆盖度（`rules/50` §3a–§3c、阈值 T08/T10–T12）。

---

## 一、铁律

0. **先查缓存再取数。** 取数前依次查三处：项目根 `./cache/`（`company` / `agent_month` / `inventor` / `docx` / `pdf`）、`results/` 下同一批次的既有结果、skill 包内 `cache/` 与 `scripts/cache/`。
   命中条件：`_schema` 与当前口径一致，且在有效期内。不满足按未命中处理，重新取数；取数完成后用 `cache.py set` 写回。报告标注「缓存值（原始取数日）」。
   细则见 `data-sources.md` §4（缓存协议）与 §12（缓存命名空间）。外部取数走 incoPat 浏览器，首次检索时脚本自动登录（凭据在 `~/.incopat/credential`，见 `data-sources.md` §5.1）；缺凭据时提示先 `inco_login.py --save`。
1. **全维判定**：11 个维度每项都要出结论，任一维不过（且未被豁免）→ 非正常。
2. **不因"已定案"跳过维度**：已有一维不过，其余维照常取数、照常记录。省成本靠缓存，不靠短路。
3. **数据拿不到 → 待核查**：不默认通过（漏判），也不凭空判不过（误伤）。
4. **每维结论挂证据（证据落 `cases/*.json`，不上报告纸面）**：文本维写段落/权项号；外部维写来源 + 取数日；缓存命中写「缓存值（原始取数日）」。报告正文只写一句人话原因（见第五节）。**③ 创新度必须给对比文件号 + 覆盖度 k/N + 逐特征对照表**，否则结论不可复核。
5. **判据以原文为准**：技术方案看正文，名称和外部数据只作补充。用户给的申请人与著录项不一致 → 必须标注。
6. **只按本文件与 `rules/` 列出的判据判**：不自创指纹、模板套话、相似度打分一类标准。
7. **豁免不是通过**：被资质豁免的维度状态是 `waived`，照常算出结论但不参与否决，报告必须展示原判定。

## 二、判定流程（按顺序跑；顺序只影响成本，不改结论）

```text
第 -1 步 查缓存（铁律 0，必做）：./cache 各命名空间 + results/ 同批结果 + skill 包内 cache
         命中 → 直接用，报告标「缓存值（原始取数日）」；只补缺失/过期的维，别重查
         同一公开号在 results/*/cases/ 已有案件文件 → 直接读该文件，按各维数据源有效期
         （company 90 天 / inventor 7 天 / agent_month 1 天）逐项判断，只重跑过期维
第 0 步  读案：申请人 / 第一发明人（(72) 第一位）/ 其余发明人 / 代理机构 / 代理人
第 1 步  前置资质：查申请人是否专精特新小巨人或省级专精特新
         ├ 命中 → 企业类维度标 waived（rules/80-exemptions.md）
         └ 未命中 → 企业类维度正常判
第 1.5 步 申请人维度（rules/10-applicant.md）：
         ①类型 / ①科技属性 / ①社保（T01）/ ①主营匹配
         1.1 授权发明专利（T02）：每案都判——到本案申请日授权发明专利 ≥1 → 过；0 件 → 非正常
第 2 步  文本维（免费）：③四类归类、④撰写、违法公德
         ③：非四类 → 直接过（不看创新度）；生活类/计算机算法 → 不过；
             机械装置/方法步骤图的系统 → 转第 2.5 步
第 2.5 步 ③ 创新度（只在第 2 步归到机械装置/方法步骤图时才跑，要取数）：
         拆创新点 → 布尔+语义两路检索 → 逐特征对照算覆盖度
         ≥80% 且差异为常见替换/公知常识 → 非正常；否则过；检索不全 → 待核查
第 3 步  ⑥多件相似（批内有多份文本才跑）
第 4 步  ⑤ 发明人件数（rules/20-inventor.md）
         a. 取第一发明人记录：窗口 = 本案申请日往前 12 个月（不论位次，按申请号去重）
         b. 剔重名 → 有效记录集合（单/多发明人两条路径）
         c. 有效件数 N ≥5 → 非正常；N <5 → 通过
第 5 步  跨机构（复用第 4 步 b 的集合，不重复检索，rules/30-cross-org.md）
         剔重名后的申请人群 → 关联聚组 → 组数 ≥3 → 非正常（1–2 组通过）
第 6 步  ② 代理师：同样锚本案申请日往前 12 个月，总量 ≥300 → 非正常；查无此人 → 待核查
第 7 步  汇总
         任一 fail（未豁免）→ 非正常
         否则有 pending → 待核查
         否则 → 正常
```

**成本顺序**：第 2–3 步本地；第 2.5 步一次布尔 + 一次语义检索（incoPat 浏览器，无接口费用，缓存 7 天）；第 1.5 步 1.1 每案一次申请人口径检索（缓存 90 天）；第 4、5 步共用一次发明人检索（incoPat 浏览器，无接口费用）；第 1、6 步各一次工商/代理量查询（走缓存）。

**窗口统一锚点**：所有"12 个月"都从**本案提交申请那天**往前推（无申请日则用查询日），报告必须写明锚点。

## 三、维度总表

| 维 | 依据 | 通过 | 一票不过 | 可豁免 | 细则 |
|---|---|---|---|---|---|
| ①类型 | 申请人性质 | 企业 | 院校、医院、自然人、文化/传媒/茶业 | ✅ | `rules/10-applicant.md` |
| ①科技属性 | 名称/经营范围 | 强/弱科技属性 | 无研发类业务 | ✅ | 同上 |
| ①社保 | 企查查 | ≥10 人（3–10 灰区） | <3 人 | ✅ | 同上 |
| ①主营匹配 | 技术对象 × 经营范围 | 一致/相邻 | 无关 | ✅ | 同上 |
| 1.1 授权发明专利 | incoPat | 授权发明专利 ≥1 | 0 件 | ✅ | 同上 |
| 发明人件数 | incoPat | 剔重名后 <5 件 | ≥5 件 | ❌ | `rules/20-inventor.md` |
| 跨机构（2.1） | incoPat + 企查查 | 关联聚组 1–2 组 | 无关联组数 ≥3 | ❌ | `rules/30-cross-org.md` |
| ②代理量 | 香橼树 | <300 件/12 月 | ≥300 件 | ❌ | `rules/40-agency.md` |
| ③技术领域 | 文本（+ 仅四类内才检索） | 非四类一律过；机械装置/方法步骤图须创新度够（覆盖度<80% 或有实质差异） | 生活类、计算机算法；机械装置/方法步骤图中单篇覆盖≥80% 且差异为常见替换/公知常识、单篇100%、两篇拼凑 | ❌ | `rules/50-drafting.md` §3a–§3c |
| ④撰写 | 文本 | 有多级布局 | 独权写死 | ❌ | 同上 |
| ⑥多件相似 | 批内文本 | 不成组 / 跨产品 | 复制型 / 拆分型 | ❌ | `rules/60-multi-similar.md` |
| 违法公德 | 文本 | 无 | 违法/公德/公共利益 | ❌ | `rules/70-illegal.md` |

阈值只在 `rules/00-thresholds.md` 维护，别处一律引用，不重复写数字。

## 四、状态与结论映射

| 状态 | 含义 | 参与否决 |
|---|---|---|
| `pass` | 通过 | — |
| `fail` | 不过 | ✅ |
| `pending` | 待核查（数据缺失/需人工） | 不否决，但结论降为"待核查" |
| `na` | 不适用（单件不涉⑥、窗口内只有本案一家） | — |
| `waived` | 豁免（企业类维度 + 专精特新） | ❌ |

结论：任一 `fail` → 非正常；无 fail 但有 `pending` → 待核查；全 pass/na/waived → 正常。

> `pending` 是内部状态，**不上报告**：报告只呈现「不过 / 过」。无 fail 但有 pending 的案子，按"不默认放过"写成不过，原因写「关键数据缺失，未取得可放行的证据」。

## 五、报告标准（固定格式）

**报告由 `scripts/build_report.py` 生成，固定两段：总览 + 逐件结论。**

### 1 总览

- 结论表：`不过 N` / `过 M` 两行件数
- 一行分布：`不过项　授权发明专利 19 件　·　多件相似 13 件`

### 2 逐件结论

每件一条，标题一行 + 不过原因一到两句：

```text
### 1. 一种双向密封球阀密封结构 · 埃里克阀业（江苏）有限公司 · 不过

- 不过原因：申请人到基准日没有授权发明专利（0 件）；本批 13 件全围绕「阀门」同一产品线（球阀、蝶阀、截止阀、密封组件、保护套），是同一产品的不同结构件分别申请
```

过件只写标题行（`· 过`）。

**不过原因怎么写**（给律师看，必须是"事实 + 依据"两句，不出现专利术语）：

- 不写「权1 / 权2 / 独权 / 从权 / 权利要求 N / 上位 / 退路层」这类术语。需要指代时写「排在最前面的那条权利要求（决定保护范围宽窄的一条）」「后面几条权利要求」。
- 事实：把"写死了什么"落到原文，括号内给一段短引文 + 条数，例如「后面 7 条只是继续补其他芯片（U3、U7、U2）的引脚接法」。
- 依据：一句话点明为什么算不过，例如「保护范围一开始就锁死在具体电路接线上，这条被驳后没有更宽的方案可以退」。
- 申请人维度直接说主体性质，例如「申请人是自然人（孟繁硕）」「申请人是高等职业院校（福建船政交通职业学院）」。
- 数据维度给窗口与件数，例如「本案申请日往前 12 个月（2025-08-03～2026-08-03）内剔除同名他人后仍有 9 件是他本人的申请」。

### 3 不写入报告的内容

| 不写 | 说明 |
|---|---|
| 附注 / 数据来源 / 取数日 / 复核项 / 取数成本 | 写入 `cases/*.json`，报告不列 |
| 「待核查」 | 报告只呈现「不过 / 过」两态。缺数据且无其它不过项时判不过，原因写「关键数据缺失，未取得可放行的证据」 |
| 内部代号 | 不写 型A/型B（用复制型/拆分型或直接描述）、不写 ①②⑥、不写 T08/T10 等阈值编号 |
| 维度代号 + 缩写 | 不过原因用完整句子陈述，例如「申请人是文化/传媒类公司（国标行业：文化、体育和娱乐业）」，不写「①类型 文化/传媒类申请人」 |

### 4 维度显示名（与人话一致）

申请人类型 / 科技属性 / 社保人数 / 主营匹配 / **授权发明专利** / 发明人申请件数 / 发明人跨机构申请 / 代理师代理量 / 技术领域创新度 / 撰写布局 / 多件相似 / 违法公德

维度名与原因句写入 `cases/*.json` 的 `dims` / `notes` / `fail_reasons`，报告取 `fail_reasons`。
