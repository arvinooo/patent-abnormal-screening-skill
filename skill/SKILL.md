# 专利非正常申请筛查

## 一、执行顺序

```text
第 0 步  批次 B01、B02        每机构 1 次查询   命中整批定非正常
第 1 步  文本 T01–T16         0 查询
         硬证据（第十二条、第十条）单独成立  → 非正常
         软证据 + 第十六条同时成立          → 非正常
         单一软证据或单一第十六条            → 存疑
         无命中                             → 正常
第 2 步  主体 T20–T27         只对存疑案，按申请人/发明人去重取数
         任一项成立 → 非正常；能证明清白 → 正常；数据缺失 → 待核
```

顺序是实测出来的，不是流程偏好：批次每 11 次查询能定 228 件且零误伤，排在文本前整体精确率 68%→91%。推导见 `references/ordering.md`。

**档位**：T08（第十二条）、T04（第十条）、T03（人工确认的工站式）是硬证据；T01、T02、T05、T06、T07、T10、T15、T16 是软证据，须与 T11 同时成立。
**T11 护栏**：背景技术引用了在先文献、有性能测试表、有测试结果数值，有其一即视为有验证结构。
**实用新型**不适用第十六条，只按手段判：硬证据 → 非正常，软证据 → 存疑。

## 三、步骤与成本

| 步 | 做什么 | 成本 |
|---|---|---|
| -1 | 查缓存：`./cache/`、`results/` 同批结果、skill 包内 cache；命中直接用，标注原始取数日 | 0 |
| 0 | 读案：首页著录项（申请人、发明人、代理机构、申请日、类型） | 0 |
| 1 | 批次：B01、B02，一条机构查询覆盖该机构 12 个月全部申请 | 每机构 1 次 |
| 2 | 文本：`procedure.md` 的抽取与计数 → 按标准逐条核 → 硬/软分档 | 本地 |
| 2b | 可选：`scripts/text_screen.py` 跑一遍做对照，脚本出三档，结论仍以人工复核为准 | 本地 |
| 3 | 主体：T20–T27，只对存疑案，按申请人、发明人去重取数 | 每人/每家各 1 次 |
| 4 | 兜底：S6 研发过程记录（前八项取不到或事实与文本不符时） | 人工 |
| 5 | 出报告：结论 + 触发项 + 证据 + 未核项 | — |

批次排在文本之前：它用 11 次查询就能定掉 60% 的批次，且实测零误伤；文本 0 成本但对正常案件的误伤率高达 54–68%，单独当结论用会把一半正常案子判成非正常。

## 四、边界

- 只判本目录列出的判据，不自创指纹、模板套话、相似度打分。
- **不在本流程范围**：创造性不足、权利要求布局过窄、同类多件拆分、违法公德。这些按审查意见或另设流程处理。
- 院校、医院不因身份命中；企业阈值不得直接套用到院校院所。
- 结构案触发 T08 时，附"核对附图"提示，须复核后再定。
- 数据拿不到记待核，不默认通过，也不凭空判不过。

## 五、报告

每件出一张判定单（字段见 `stage1-text/procedure.md` 第四节）。主体步只在判定单上追加：B01/B02 与 T20–T27 的逐项结论、数据来源与取数日、豁免标记。
