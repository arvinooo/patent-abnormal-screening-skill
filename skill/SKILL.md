# 专利非正常申请筛查

**输入**：专利公开文本 PDF（一份或多份同批）+ 申请人（不给就从著录项 (71)/(73) 取）
**输出**：正常 / 非正常 / 待核查，逐维结论 + 证据（段落号、权项号、数据来源和取数日）

## 铁律

1. **全维判定**：①申请人 ②代理 ③技术领域 ④撰写 ⑤发明人 ⑥多件相似 + 违法公德，**每一维都要出结论**。任一维不过 → 非正常。
2. **不因"已定案"跳过任何维度**。测试阶段就是做全量回归：PDF 维已不过，外部维照样取数、照样记录。**省成本靠缓存，不靠短路**。
3. **数据拿不到 → 标「待核查」**：不默认通过（漏判），也不凭空判不过（误伤）。
4. **每维结论挂证据**：PDF 段落/权项号；外部数据写来源 + 取数日期；缓存命中写「缓存值（原始取数日）」。
5. 判据以 **PDF 原文**为准，名称和外部数据只作补充。用户给的申请人与著录项不一致 → 必须标注。
6. **只按本文件列出的维度判**：不自创文本指纹、模板套话、相似度打分一类判据。

## 维度总表

| 维 | 依据 | 通过 | 一票不过 | 证据锚点 |
|---|---|---|---|---|
| ①类型 | PDF (71)/(73) | 企业 | 院校、医院、自然人、文化/传媒/茶业 | 申请人名称 |
| ①科技属性 | PDF 名称（经营范围可外部补） | 强/弱科技属性 | 无研发类业务 | 名称、经营范围 |
| ①社保 | 企查查/天眼查 | ≥3 人 | <3 人 | 参保人数 + 取数日 |
| ①主营匹配 | PDF 技术对象 × 经营范围 | 一致 / 相邻 | 无关（无交集） | 经营范围 |
| ②代理师代理量 | 香橼树 | ≤500 件/年 | >500 件/年 | 代理师 + 当年累计 |
| ③技术领域 | PDF [0001] + 权1 | 非清单，或有技术链 | 清单内 + 无实质技术链 | 段落号 |
| ④撰写 | PDF 权利要求书 | 多级布局 | 独权写死（两条） | 权项号 |
| ⑤a 当年件数 | mindflow MCP | 发明人（不论位次）当年 ≤5 件 | >5 件 | 检索式 + 按申请号去重件数 |
| ⑤b 申请人一致性 | mindflow MCP | **第一发明人**名下全部专利申请人 = 本案 | 任一篇不一致 | 异申请人清单 |
| ⑥多件相似 | 组内多份 PDF | 不成组 / 跨产品 | 型A / 型B | 组内件清单 |

## 执行顺序（全维跑，先免费后付费）

| 序 | 维度 | 来源 | 单案成本 |
|---|---|---|---|
| 0 | PDF 提取（著录项/权1/技术领域） | `scripts/extract_pdf.py` | 0 |
| 1 | ①类型 | PDF | 0 |
| 2 | ③技术领域 | PDF [0001] + 权1 | 0 |
| 3 | ④撰写 | PDF 权利要求书 | 0 |
| 4 | ①名称科技属性 | PDF 名称 | 0 |
| 5 | 违法/公德 | PDF 权1 + 发明目的 | 0 |
| 6 | ⑥多件相似（有同批 PDF 才跑） | 本地多份 PDF | 0 |
| 7 | ②代理量 | 香橼树（浏览器） | 0 额度、耗时 |
| 8 | ①社保 + 主营匹配 | 企查查 | 积分 |

- 顺序只省成本、不改结论。**第 1–9 步每份 PDF 都要跑到**；缺数据的维写「待核查」，不写「通过」。

- 同主体多案 → 社保只查 1 次；同代理师 → 代理量只查 1 次；同第一发明人 → MCP 只查 1 次。全走缓存。

## 各维判据（够用版；细则与边界见 rules.md）

### ① 申请人（四项全过才过）

1. **类型**（一票，按设立性质判，不看名称字面）：院校（大学/学院/学校/研究所/研究院，含军队院校）、医院（含医学院校附属医院）、自然人（含个体户、家庭式组合）、文化/传媒/茶业 → 不过。
   - 边界：「××职业培训学校有限公司」＝企业，不是院校。
   - 院校/医院在工商库查无主体是正常的，按 (71) 判类型即可。
2. **科技属性**：高企/科技型中小企业/专精特新认定，或名称、经营范围含 科技/技术/智能/电子/软件/网络/数据/生物/医药/新材料/新能源/半导体/自动化/通信/检测/机器人/光电，或含 技术开发/技术咨询/研发/软件开发/系统集成/集成电路设计/检验检测 → 过。名称带"科技"但经营范围纯贸易/咨询 → 弱。主业文化/传媒/茶业/贸易/餐饮/咨询/投资/房地产/物流且无研发类经营范围 → 不过。
3. **社保**：**<3 人 → 不过**（硬判据）；3–10 灰区（结合企业规模、研发实力）；≥10 → 过。
4. **主营匹配**：PDF 的技术对象/应用场景 vs 经营范围。一致（主营产品线）→ 过；相邻（同产业链上下游）→ 过，说明理由；无关（无交集）→ 不过。

### ② 代理公司（异常 → 不过，且**连坐**：该机构代理的本案直接非正常）

**判据：代理师当年（1月1日至今）累计代理量 >500 件/人 → 不过。**

机构层面的两项不判：
- **非正常申请预警 / 重点监控名单**：国知局该名单为系统内网通报，不对外公开，无法获得完整名单。公开的行政处罚决定书只是零星个案，可作旁证，不作为通过依据。
- **机构申请量短期波动**：无既定阈值。

取数见 data-sources.md §2；报告写明取数区间与日期。

### ③ 技术领域

高风险四类：**机械装置 / 生活类发明创造 / 计算机算法 / 方法步骤图的系统**。

判定：命中清单 **且** 方案无「技术问题—技术手段—技术效果」实质链 → 不过。
三个问题，**全"否"才判过**：

1. 权1 里有没有承载技术效果的**物理结构或工程手段**？（还是只有计算步骤、流程、模块名）
2. 把计算/步骤去掉，方案还剩什么实质内容？（什么都不剩 → 疑）
3. 技术效果是不是各特征效果的**简单相加**、没有协同（1+1>2）？（是 → 疑）

边界：产品级结构改进有结构-效果链（如风道解决冷气分布不均/凝露）→ 不因"机械"字样判不过；判定看 PDF 技术领域原文，不是 IPC 号机械套用。

### ④ 撰写（仅两条，命中任一 → 不过）

1. **缺多级布局**：独权即最窄——整机部件、整条工艺、全部优选参数写进独权，从权只能补无关细节或换个说法，没有退路。
   健康形态：独权上位概括，从权逐层收窄（先加功能 → 再加结构 → 落参数/材料），任一层无效下一层兜得住。
2. **步骤顺序或参数范围写死**：方法类把步骤全序（S1→S2→S3…）连同工艺参数（温度/时间/浓度/转速）写进独权；产品类写死只对应某台样机的定量限定（"行程20mm""八个阀门"）且该数值并非解决技术问题所必需。
   - **不算写死**：组合物/材料类的配比区间（重量份）是该领域常规写法；数值放从权、独权只写"预设值/阈值"等变量表述。

「修改后仅改附图/调整措辞、无实质改进」**不在判据内**，不作为④依据。

### ⑤ 发明人（两条并列，任一命中 → 不过）

**范围：只查本案第一发明人**（(72) 第一位）。多位发明人时只拿第一位去查，一次检索结果同时支撑 5a 和 5b。

**a. 当年件数**：该姓名**当年（1月1日～查询当日）申请、发明人一栏出现该姓名**的专利件数 **>5 → 不过**（=5 通过）。
- 检索式：`IN:(姓名) AND APD:[YYYY0101 TO 今天]`；不论排第几发明人都计入。
- **按申请号去重计件**：A/B 文、一案双申会产生多条公开文本，raw total 不能直接当件数。
- `F_IN` 字段只含第一发明人，会漏掉该姓名作为共同发明人的申请，不用于本判定。
- 数据源：MCP 结构化记录按申请号去重为准；浏览器 `IN:(姓名)` 结果表作粗筛与交叉校验；两源不一致且落在 >5 → 标「待核查」。

**b. 申请人一致性**：以 `inventors[0]`＝该姓名锁定身份后，其名下全部专利的申请人必须**完全等于本案申请人**；任一篇 ≠ → 不过。
- **证据分层**：≥2 位本案发明人共同重合于同一异申请人 = 强证据；仅 1 人重合 = 弱证据（疑似同名碰撞，仍判不过，标「待人工复核」）。
- **已知偏差（必须写进报告）**：母子公司分流、同名碰撞会误伤；报告列出异申请人名单，供人工降级。
- PDF 无 (72) / 全部「请求不公布姓名」→ **⑤不适用**（跳过，不计待核查，不影响结论）。
- 数据：优先 `scripts/mindflow_inventor.py`（浏览器，0 积分）；不可用时退 MCP。同批同一第一发明人只查一次（cache/inventor.json），5a/5b 从缓存现算。
- 公开滞后：发明申请 18 个月公开，当年计数是**下限**。

### ⑥ 多件相似申请（跨案一票项，先成组再判）

**成组**：同一申请人/关联主体 **≥2 件** + 12 个月内 + 组内每件都有 PDF。只有 1 件的主体不构成组，不得并入邻组；关联主体并组须其自身 ≥2 件或有股权/实控人证据。

| 型 | 判据 |
|---|---|
| A 复制型 | 正文 20 字 shingle 重合率 **≥50%**，技术问题/原理一致、差异仅参数 |
| B 拆分型 | 组内各件发明名称**全部围绕同一产品/设备**（产品级尺度，非行业级）→ 一票非正常 |

同一产品的结构件/控制方法/装配工艺/配套方法都算同主题；组内跨多类设备 → **整组不构成**，不做子组拆分。
判例：同上产品 9 件（全打印机）= 型B；跨设备 9 件（硫化机+输送线+模具）= 不构成。用户口径：**⑥这一块不需要太严**。

### 违法 / 公德 / 公共利益（独立一票项）

发明目的直接违法（赌博设备/吸毒器具/伪造货币、票据、公文、证件、印章、文物的设备）、违反社会公德（凶杀/淫秽/暴力恐怖/违反基本人伦）、妨害公共利益（严重污染环境、破坏生态、危害公共安全、涉政党象征标志、外观含国旗国徽）→ 非正常，任何申请人。

## 外部数据缓存（查一次就落盘）

**不重查 = 不花额度。** 每次取数前先 `get`，命中直接用。

| 命名空间 | 键 | 存什么 | 有效期 |
|---|---|---|---|
| `company` | 申请人全名 | 参保人数 / 经营范围 / 行业 / 标签 / 规模 | 90 天 |
| `agent` | 代理师姓名 | 当年累计代理量 + 取数日 | 1 天 |
| `inventor` | **第一发明人**姓名 | 检索原样结果（组数/条数/记录行：申请号+申请日+申请人） | 7 天 |
| `pdf` | PDF 文件名 | 提取字段 + 全文 txt（由 extract_pdf.py 管，不是 cache.py） | 永久 |

```bash
python3 scripts/cache.py get  company  "深圳XX有限公司" --max-age 90   # exit 0=命中，1=未命中/过期
python3 scripts/cache.py set  company  "深圳XX有限公司" --json '{"insured":9,"scope":"...","industry":"...","tags":[]}'
python3 scripts/cache.py list inventor
python3 scripts/cache.py prune --max-age 365
```

- 命中（exit 0）→ 直接用，报告标「缓存值（YYYY-MM-DD 取数）」；未命中/过期（exit 1）→ 真去查，查到立刻 `set`。
- **派生结论不缓存**：阈值会变、原始数据不变。⑤a/⑤b、①社保是否<3、②是否>500 全部每次现算。
- 有效期依据：社保是年报公示口径（90 天）；代理量天天涨（1 天）；发明人件数一周内不会翻转阈值（7 天）。
- 缓存目录默认 `./cache`，可用环境变量 `PATENT_CACHE_DIR` 改。

## 输出

**交付物只有两个：`report.md` + `report.pdf`。** 同一内容，md 用来 diff/入库，pdf 直接给人看。不产出 xlsx/csv；逐案 `cases/<公开号>.json` 只作统计的中间件，不算交付物。

  "first_inventor": "王键", "app_date": "2026-01-19", "conclusion": "非正常",

### 出报告

```bash
python3 scripts/build_report.py <cases目录> -o report     # -> report.md + report.pdf
```

报告固定含 8 节，**统计是脚本算的，不靠手数**：

1. **结论概览**：正常 / 非正常 / 待核查 的件数和占比
2. **各维度命中统计**：每维的 不过 / 待核查 / 不适用 / 通过 + 不过率（一票项和条件项分列，一眼看出这批栽在哪）
3. **命中项组合**：组合 → 件数 → 公开号；外加命中项数分布（挂 1 项多少件、挂 3 项多少件）
4. **逐案总表**：17 列，过/挂/待/— 单字标记，A4 横排
5. **复核清单**：必须人工看的案子 + 为什么
6. **待核查清单**：每案缺哪一维，缺什么数据
7. **数据来源与取数日**：谁查的、哪天查的、缓存命中还是当日取
8. **取数成本**：MCP 调用次数 × 积分、企查查积分消耗

报告头部必须写：生成时间、案件数、**阈值快照**（这批用的是哪版阈值，方便日后回溯为什么判得不一样）。

## 法律锚点（国知局令第77号）

| 条款 | 情形 | 对应维度 |
|---|---|---|
| 第三条(一) | 多件申请内容明显相同 / 特征要素简单组合 | ⑥ 型A |
| 第三条(二) | 编造伪造内容数据效果；抄袭、简单替换、拼凑 | ③ + 人工复核 |
| 第三条(三) | 主要为计算机技术等随机生成 | ③ |
| 第三条(四) | 明显不符合技术改进/设计常理；变劣、堆砌、非必要缩限 | ③④ |
| 第三条(五) | 无实际研发活动提交多件申请 | ①社保/规模、⑤a |
| 第三条(六) | 恶意分散、先后、异地提出 | ⑥ 型B |
| 第三条(七) | 不正当转让受让 / 虚假变更发明人 | ⑤b |
