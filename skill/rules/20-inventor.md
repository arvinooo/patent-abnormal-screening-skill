# 20 发明人：剔重名 → 计数

> 同名的人混在一起必冤：先把同名他人剔掉，再数件数。
> **本文件只负责计数与剔重名**；"名下还有别家申请人"由 `rules/30-cross-org.md` 判。

## 0 适用范围

- 只查**第一发明人**（(72) 第一位）。其余发明人不单独查（2.1 会用到他们的名字，但不检索他们名下）。
- 窗口：**滚动 12 个月** = 查询日往前推 365 天（T03）。
- 检索：`IN=(姓名) AND AD=[窗口起 TO 查询日]`，**不论发明人位次**都计入候选。
- 按**申请号**去重（A/B 文、一案双申会产生多条公开文本）。

## 1 取数（一次调用，两个用途）

每个第一发明人取一次记录集合，字段至少要有：

| 字段 | 用途 | 来源 |
|---|---|---|
| `app_no` | 去重、连接 | incoPat 结果行 |
| `app_date` | 窗口过滤 | incoPat 结果行 |
| `title` | 人工复核用 | incoPat 结果行 |
| `co_inventors` | **剔重名（共同发明人比对）** | 反查：其余发明人各跑一次同窗口 `IN=(…)`，按申请号求交集 |
| `applicants` | 2.1 跨机构 | incoPat 结果行 |
| `ipc`（主分类） | **剔重名（领域比对）** | incoPat 结果行 |

> incoPat 结果行默认不含发明人名单，且「显示字段」里的发明人列在自动化下勾不上；因此共同发明人改用**反查法**（见 `data-sources.md` §9）。结果行拿不到 IPC → 该案 1.2 标 `pending`。

## 2 剔重名（判"这件是不是这个人的"）

### 2.1 本案只有 1 个发明人

只能靠领域判断（没有共同发明人可比）：

```text
若 ipc(该件) 与 ipc(本案) 一致或相似 → 是同一人 → 保留
否则                                → 判重名 → 剔除
```

### 2.2 本案有多个发明人（其余发明人集合 R）

优先用身份锚，领域作为退路：

```text
若 co_inventors(该件) ∩ R ≠ ∅ 且 重合的名字不是常见名 → 是同一人 → 保留
否则若 ipc(该件) 与 ipc(本案) 一致或相似         → 保留（领域兜底）
否则                                            → 判重名 → 剔除
```

**常见名不作锚**：`张伟、王芳、李娜、刘洋、王伟、李伟...` 这类高频姓名出现在共同发明人里，不能证明是同一人（概率太高）。名单放 `data-sources.md` §9 的 `common_names`，可扩展。

### 2.3 领域口径

| 判定 | 规则 |
|---|---|
| 一致 | IPC 主分类**前 4 位**相同（如 `F16K5/06` 与 `F16K5/08` → `F16K`） |
| 相似 | IPC 主分类**前 3 位**（大类）相同（如 `F16K` 与 `F16D` → `F16`）… 注：前 3 位是"小类"，报告里写清是比到哪一级 |
| 不同 | 前 3 位不同 |

> 实现时统一写成"取前 N 位"参数，N 默认 4（一致）/ 3（相似），别写死字符位置。

### 2.4 第二锚（降低两个方向的误差）

| 情形 | 处理 |
|---|---|
| 该件申请人 = 本案申请人 **且** 领域一致 | 铁定同一人 → 保留 |
| 领域一致 **但** 申请人不同 | 可能同行业同名他人 → 保留但标 `pending`（待人工），不硬算进计数 |

**副作用（必须写进报告）**：同一人跨领域创新会被判重名（少计，偏松）；同行业同名者会被计入（多计，偏严）。

## 3 计数与判定

```text
N = |有效记录集合|（按申请号去重，含本案）
N ≥5 → 发明人件数不过 → 非正常
N <5 → 发明人件数通过
```

本案本身也是这个人在窗口内提交的一件申请，计入 N；只有"同名他人"才剔除。
报告与证据写"有效 N 件（含本案）"，不写"剔除本案后"。

**这里不设"新公司豁免"和"实用新型替代"**——用户已确认严格口径是有意的。

申请人有没有授权发明，由 1.1（`rules/10-applicant.md` 1e）判，不在本维。

## 4 跨主体——见 `rules/30-cross-org.md`

拿第一发明人查他名下所有专利、看申请人有没有别人，这件事由 `rules/30-cross-org.md` 判：

- 先剔重名（本文件 §2）
- 取剔重名后记录的申请人群 → 关联聚组 → **1–2 组通过、≥3 组不过**
- 窗口与 1.2 同一个（锚本案申请日往前 12 个月）

**允许 2 家（本案 + 1 家）**，所以"母公司报一份、子公司报一份""公司报 + 老板个人报"不会被误杀。

## 5 缓存

| 命名空间 | 键 | 存什么 | 有效期 |
|---|---|---|---|
| `inventor` | 第一发明人 + 窗口 + 共同发明人集合 | 原始记录（含 co_inventors / applicants / ipc）+ 检索式 + 取数日 | 7 天 |
| `inventor_identity` | 第一发明人 + 本案申请人 | 剔重名结果（保留/剔除清单 + 理由） | 7 天 |

派生结论（N、是否过线）**不缓存**，每次现算。

## 6 报告展示

本维只出件数结论；报告里落到一句人话（证据写进 `cases/*.json`）：

```text
### 3. 风电土建测量用测量装置 · 天津德吾安环境修复有限公司 · 不过

- 不过原因：申请人到基准日没有授权发明专利（0 件）
```

（内部记录：名口径 7 件 → 剔除同名他人 7 件 → 有效 0 件 <5 → 发明人件数通过；剔重名后仅本案 1 家 → 跨机构 1 组 → 通过。）

## 7 已知坑

1. **公开滞后**：发明申请 18 个月才公开，12 个月窗口内的申请很多还没公开 → 计数是**下限**，方向偏松。报告标注。
2. **常见名总量溢出**：如"王猛"命中上万组 → 不要逐条拉全量，直接标"常见名，计数不可采信 → `pending`"。
3. **一案双申**：同一申请号既有发明又有实用新型文本 → 只算 1 件。
4. **本案无 IPC**（未公开、代理机构没填）→ 领域比对退化为"技术领域原文关键词"，标 `pending`。
5. **姓名带身份证号**：明细表里形如 `林美华150428199609244921`，必须先剥掉身份证号再检索；报告里显示打码版本。
