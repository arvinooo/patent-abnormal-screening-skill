# 30 跨机构申请（2.1）

> 判什么：这个第一发明人，在**本案申请日往前 12 个月**内，是不是**在多家互不相关的机构名下**报专利——也就是"一个人替好几家公司批量报"。
> 对象是**人**，不是单件案子；不合格时该人在本批负责的案子**全部命中**（人级连坐）。
>
> 判的是"剔重名之后，这个人在几家互不相关的机构报过"：本案 + 1 家（2 家）通过，3 家起看关联。

## 1 判定流程

```text
① 取集合 S = 1.2 剔重名后的有效记录集合（不重新检索）
② 从 S 里收集申请人：current_applicants ∪ original_applicants（去重）
   ├ 只有本案申请人 1 家 → 不适用（na）
   └ 2 家及以上 → 进入③
③ 按"关联关系"把机构聚成组（并查集 / 传递闭包）
④ 组数 1–2 → 正常（本案 + 1 家也允许）
   组数 ≥3 → 非正常（一票否决，T04）
```

**为什么先聚组再数**：母公司报、子公司也报，机构名好几个但其实是同一集团，不该算"跨机构"。聚组后按"组数"判，才抓得住真正无关联的分散申报。

## 2 关联关系怎么判（近似口径，已定）

**不查股权**（不做穿透，不增加接口和额度）。用下面四条任一成立即算关联：

| 依据 | 说明 |
|---|---|
| 同法定代表人 | 两家公司法定代表人是同一自然人 |
| 同注册地址 | 注册地址字符串一致（归一化后） |
| 名称互相包含 / ≥6 字共同前缀 | 如"中国电建集团湖北工程"与"中国电建集团河南工程" |
| 自然人 ↔ 其任法定代表人的公司 | 申请人里有自然人，且该姓名 = 另一申请人的法定代表人 → 视为关联 |

**传递闭包**：A 与 B 同法人、B 与 C 同地址 → A/B/C 算**一组**。

数据：企查查 `get_company_registration_info` 取 `法定代表人` + `注册地址`，缓存 90 天；同一法定代表人只查一次。自然人申请人不需要查工商。

## 3 判定表

| 情形 | 判定 |
|---|---|
| 剔重名后只有本案 1 家 | `pass`（报告写"1 组"） |
| 聚组后 1–2 组 | `pass` |
| 聚组后 ≥3 组（= 至少 3 个互不相关主体） | `fail`（非正常） |
| 第一发明人是常见名（名下 >1000 组） | `pending`（机构数不可采信，待核查） |

> 注：聚组后 ≥3 组本身就意味着"至少 3 个互不相关的主体"，所以**组数 ≥3 = 无关联组数 ≥3**，不必再做一步"检查关联"。

## 4 连坐与报告

- 该第一发明人在本批负责的**所有案子**都命中（只限本批，不碰其他批次/客户）。
- 报告必须写：

```text
2.1 跨机构：第一发明人 林美华
  有效记录 4 件，涉及申请人：天津德吾安环境修复有限公司
  → 聚组 1 组 → 不适用
```

```text
2.1 跨机构：第一发明人 王猛
  有效记录 12 件，涉及申请人：A公司、B公司、C公司
  → A与B：同法定代表人（张三）→ 合并为 1 组；C 无关联
  → 聚组 2 组 → 通过
```

## 5 与其他判定的关系

| 维度 | 判什么 | 结论 |
|---|---|---|
| 发明人件数 | 剔重名后这个人在窗口内报了几件 | ≥5 → 不过 |
| 研发能力 | 本案申请人在基准日有没有授权发明 | 0 件 → 不过 |
| 跨机构（本文件） | 这个人在几家互不相关的机构报过 | ≥3 组 → 不过 |

报告里统一写"跨机构"。

## 6 已知坑

1. **公开滞后**：12 个月内的申请很多还没公开 → 机构数会少算，方向偏松。报告标注。
2. **公司改名/更名**：会被算成两家，可能误判；用标准化名称缓解，仍可能撞，报告标注。
3. **同名他人**：必须先过 1.2 剔重名，否则常见名（如"王猛"）会直接爆表。
4. **关联判定是近似**：漏判（真关联没识别 → 误判不过）和错判（同名地址误关联 → 放松）都会有，报告把依据逐条写出来供人工复核。
