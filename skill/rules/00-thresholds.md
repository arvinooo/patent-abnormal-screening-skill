# 00 阈值总表（唯一出口）

> 改阈值只改这里。`rules/` 各处、`scripts/text_screen.py` 的常量都引用本表，不重复写数字。
> 每批的阈值快照写进 `cases/_batch.json` 的 `rules_version`；报告正文不印快照。

## 结论规则

```text
第一层（手段、效果）：两项都成立 → 非正常；一项 → 存疑，进第二层；零项 → 正常，放行
第二层（只对存疑案）：任一项成立 → 非正常；全不成立 → 正常；数据缺失/灰区 → 待核
实用新型不适用效果判据，第一层只判手段：成立记存疑，不成立记正常
```

## 第二层：主体面板

只判**文件之外的主体事实**。PDF 主体由第一层判，批次由第二步判，本层不重复。

八项全跑，任一成立即非正常；全不成立即正常。主体身份本身不作理由，每项都要"身份 + 事实"。

| 编号 | 项 | 成立条件 | 窗口 | 数据源 |
|---|---|---|---|---|
| T20 | 发明人有效件数 | 剔重名后 ≥5 件 | 本案申请日往前 12 个月 | incoPat |
| T21 | 跨机构组数 | 聚组后 ≥3 组 | 同上 | incoPat + 企查查 |
| T22 | 代理师代理量 | ≥300 件；查无此人记待核 | 同 T20 | 香橼树（本所口径） |
| T23 | 授权发明专利 | 0 件且申请人为企业；院校/院所/医院/自然人不适用 | 到本案申请日 | incoPat |
| T24 | ①类型 | 自然人/个体户；或文化/传媒/茶业类且主营无交集 | — | 申请人栏 |
| T25 | ①科技属性 | 主业文化/传媒/茶业/贸易/餐饮/咨询/投资/房地产/物流，且无研发类经营范围 | — | 企查查 |
| T26 | ①社保人数 | 参保 <3 → 成立 | 取数日 | 企查查 |
| T27 | ①主营匹配 | 与技术对象无关，且非院校非医院 | — | 企查查 |

结论：任一项成立 → 非正常；全不成立 → 正常；任一项数据缺失 → 待核。

院校、医院不因身份命中：已确认正常样本的申请人中占 55%、非正常样本中占 2%。

## 边界值速查

| 情形 | 判定 |
|---|---|
| 发明：手段 + 效果 | 非正常（第一层即定） |
| 发明：手段 + 批次 | 非正常（第二层定） |
| 发明：效果 + 批次 | 非正常（第二层定） |
| 实用新型：手段 + 批次 | 非正常（第二层定） |
| 第一层只成立一项 | 存疑，进第二层 |
| 第一层两项都不成立 | 正常，不进第二层 |
| 第二层全不成立 | 正常 |
| ①社保 <3 | 成立（一票否决） |
| 主体项任一成立 | 非正常（限存疑案） |
| 发明人有效件数 = 5 | 命中（≥5 挂） |
| 发明人有效件数 = 4 | 不命中 |
| 跨机构组数 = 2 | 不命中 |
| 跨机构组数 = 3 | 查关联，无关联则命中 |
| 结构案触发第十二条 | 出结论但附「核对附图」提示，须复核后再定 |
| 机械类已记载工程参数 ≥3 处 | 不因缺实验数据认定 |
| 数据拿不到 | 待核，不默认通过，不凭空判不过 |

## 窗口锚点

所有"12 个月"都锚**本案申请日**，往前推 365 天。

取得申请日的顺序：

1. 文本著录项 (22)；
2. 明细表给了申请号时，用 incoPat 按申请人取该批案件的结果行，按申请号对上本案；
3. 以上都没有（撰写稿未提交、未公开）→ 锚点退化为查询日，报告标注。

申请号是当年顺序号，可用于判断月份量级：同一年内序号越大申请日越晚。仅作辅助，不作定案依据。
